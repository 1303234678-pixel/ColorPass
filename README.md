# JYBridge

**剪映剪辑，达芬奇调色，然后回剪映继续剪。**

绝大多数「剪映 ⇄ 达芬奇」工具在搬工程：导出 XML、渲染成片、重建草稿。
JYBridge 搬的是**可编辑结构 + 调色意图**——不落任何工程文件，也不渲染成片，
调完色写回一份**还能继续编辑**的剪映草稿。

> 三个问题，三个可独立复用的模块：
> **读得到** 加密草稿 · **摆得准** 绝对帧落轨 · **回得去** 调色回传

## 它和别的方案差在哪

| | 中间文件 | 回剪映后 | 变速 | 停用片段 | 完整性校验 |
|---|---|---|---|---|---|
| XML 类工具 | FCPXML / FCP7 XML | 新建草稿，通常只剩三轨 | 丢失，且后续整条错位 | 当正常段送，画面「复活」 | 无 |
| 回批类工具 | 渲染成片 | 一块不可编辑的成片 | 拍平 | 复活 | 无 |
| **JYBridge** | **无** | **原草稿克隆，可继续剪** | **bake 重采样，帧序一致** | **占位并禁用** | **断言失败即拒绝写回** |

「不落中间文件」的唯一例外照实说：变速段会用 ffmpeg 预渲染成等长 ProRes
（达芬奇脚本接口没有设置速度的入口）。

## 三个问题

### 读得到：加密草稿的明文三级回退

剪映 11.7+ 的 `draft_content.json` 是密文，密钥由进程启动时注入、不在磁盘上。
公开方案到这里通常止步于「请重开剪映」。JYBridge 有三级来源，按可信度依次尝试：

| 层 | 来源 | 生效条件 |
|---|---|---|
| 1 | 本地缓存 `%LOCALAPPDATA%\JYBridge\plain\<id>.json` | 磁盘指纹（密文载荷字节数 + 最后编辑时间）完全一致 |
| 2 | 剪映载入备份 `<草稿>/.backup/*.load.bak` | 写回的草稿是明文写入，备份也是明文；id 匹配且编辑时间不晚于备份 |
| 3 | 进程内存扫描 | 明文尚未被回收（体积对账，容差 320 B + 0.5%） |

实测结论：明文**只保留一段时间**。一份打开一小时、从未编辑过的草稿，内存里
可能只剩 167 KB 残片（有 `"tracks":[`、没 `"materials"`、括号不闭合）。
这与用户是否编辑无关，所以「重新打开一下」对老草稿是必要的。

效果：`jybridge check` 从 25 秒失败变为 **0.78 秒成功**（走缓存）。

### 摆得准：草稿语义 → NLE 时间线

XML / AAF 里没有「这一段是 2 倍速」「这一段被停用」这些属性。导进去按原速摆，
5 秒的段变 10 秒，**后面每一段全错位**——这就是同类工具「导进去位置不对」的根因。

| 草稿里的东西 | 常见工具 | JYBridge |
|---|---|---|
| 变速 | 丢掉，或只提示「可能对不上」 | 预渲染等长素材，帧序与剪映一致 |
| 转场 | 丢掉 | 后段起点收前段时长，位置不偏（近似，不是原生转场） |
| 停用片段 `visible:false` | 当正常段送 | 照样占位，落轨后 `SetClipEnabled(False)` |
| 复合片段 | 丢掉或拍平 | 递归展开 |
| 帧率不一致 | 累积误差 | 绝对帧号 `AppendToTimeline` |

停用片段值得单独说：它**仍然占着时间线**（实测一份 12.267 s 的草稿，有 5.5 s
是靠一条停用段撑起来的）。跳过不送会在达芬奇里留下黑场，并把后续每一段的
位置核对全部打错。

### 回得去：调色意图的回传协议

```
达芬奇调色
  → 每段打 marker，custom data 写 segment_id（身份锚）
  → 逐段 ExportLUT(33³ cube) = 每段 35,937 个采样点
  → 取送回时存的底稿快照，深拷贝（不是重建）
  → 只 append 一条 LUT 效果材质，时间线一个字节不动
  → 语义断言全过才落盘，否则拒绝写回
```

写回前的断言比的是**语义指纹**：轨道类型、段顺序、入出点、素材引用、变速倍率、
关键帧、转场/蒙版/变速/淡入淡出/复合片段引用。只比语义不比 id，所以新加的
LUT 材质不会误报。任何一项对不上就判失败——宁可告诉你写回失败，也不给你一份
「看着对、其实丢了东西」的草稿。

## 安装

**环境**：Windows 10/11 · 剪映专业版（实测 11.7.0）· 达芬奇 18+（本地实测 20.x）·
Python 3.9+（开发与测试用 3.12）

```bash
git clone https://github.com/1303234678-pixel/JYBridge.git
cd jybridge
python -m pip install -e .
python -m jybridge.install        # 装面板 + 记录源码目录与解释器
```

重启达芬奇 → 菜单 `工作区 → Workflow Integrations → JYBridge`。
在剪映里打开目标草稿 → 点面板上的 ① 送入达芬奇。

可选依赖：

```bash
python -m pip install -e ".[cover]"     # 草稿封面缩略图（Pillow）
python -m pip install -e ".[ffmpeg]"    # 变速预渲染（没有则退回近似摆放）
```

## 命令行

面板只是壳，所有能力都能单独调用、且大部分不需要达芬奇：

```bash
jybridge check                       # 读当前打开的草稿，打印结构报告（JSON）
jybridge plan                        # 只算落轨计划（dry-run，不需要达芬奇）
jybridge status                      # 面板用的状态汇总
jybridge send                        # 草稿 → 达芬奇时间线
jybridge pull                        # 达芬奇调色 → 逐段 33³ LUT
jybridge write                       # LUT → 写回一条新草稿
jybridge roundtrip                   # send + pull + write
jybridge gc --apply                  # 回收可再生缓存（默认只报告）
```

`check` / `plan` / `status` 不依赖达芬奇，可用于 CI 与批处理：
`plan` 输出的就是 `send` 内部实际使用的那份计划，包括重叠消解、变速预渲染标记、
跳过原因，可以直接 diff 两次改动前后的落轨位置。

## 模块地图

```
jybridge/
├── probe.py       认剪映工程（进程、窗口、草稿目录、锁状态）
├── memscan.py     进程内存扫描（Windows ReadProcessMemory）
├── plain.py       明文缓存 + 载入备份 + 内存，三级仲裁
├── draftio.py     草稿语义层：轨道/变速/转场/蒙版/复合片段 + 新鲜度判定
├── send.py        草稿 → 达芬奇：落轨计划、变速、停用段、marker
├── pull.py        达芬奇 → LUT：marker 身份锚 + ExportLUT
├── draftbuild.py  克隆一份草稿并追加 LUT 材质
├── write.py       写回编排 + 语义断言（structure_diff）
├── gc.py          缓存回收（只报真能删的量）
├── preflight.py   四道闸：剪映在跑 / 草稿已开 / 草稿未改 / 达芬奇可用
└── panel/         达芬奇面板（参考实现，不是全部）
```

## 限制

完整清单见 [`docs/宣传-优势与限制.md`](docs/宣传-优势与限制.md)，最需要知道的几条：

- **仅 Windows**：依赖 `%LOCALAPPDATA%` 下的剪映目录与 `ReadProcessMemory`。
- **达芬奇只收画面**：音频、文字、贴纸、滤镜、独立特效轨不送入（写回时原样保留）。
- **转场是近似的**：用时长消解重叠，不是原生转场；复杂转场观感会有差异。
- **老草稿可能要重开一次**：从没读过 + 开了一小时以上 + 不是本工具写回的草稿，
  三条件同时成立时没有明文来源，面板会明确说明原因。
- **剪映升级可能失效**：明文路线依赖剪映内部行为，版本矩阵见
  [`docs/剪映草稿字段.md`](docs/剪映草稿字段.md)。

## 隐私与边界

- 只读**本机、当前用户、当前打开**的剪映草稿；不联网、不上传。
- 不绕过剪映 VIP / 不破解授权 / 不解密他人文件。
- 设 `JYBRIDGE_NO_MEMSCAN=1` 可完全关闭内存扫描，只用缓存与载入备份
  （代价：从没读过的新草稿会读不到，需要先点一次送入并保持剪映打开）。
- 写到磁盘的东西只有三类，全在 `%LOCALAPPDATA%\JYBridge\`：LUT 工作副本、
  每次动作的报告、明文缓存（滚动保留 12 份）。

本项目与字节跳动、Blackmagic Design 均无关联。
