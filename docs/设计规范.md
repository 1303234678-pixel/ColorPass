# 面板设计规范

这份规范不是审美偏好，是**为了让「改一处不会把别处撞坏」**。面板只能跑在达芬奇里，
改完没法当场看，所以尺寸一律写成令牌，并且都有一条测试或一行日志盯着。

对应代码：`colorpass/panel/ColorPass.py` 顶部「排版令牌」一段。
预览工具：`python build/preview_panel.py ready`（不需要达芬奇）。

> **踩过的坑**（写在这里，免得再犯）
> 1. 主按钮加了 `font-weight:600`，21.2 换成粗体字面后行高 18→25，
>    实测「送入达芬奇」41 高、「写回剪映」34 高。**两个按钮的字体属性必须逐项相同。**
> 2. 页脚排在最后、又被弹簧顶到客户区底边上，Fusion 不重绘压线的行，
>    整行页脚直接消失。**最后一行下面永远留 10px 空白。**
> 3. **`WordWrap: True` 不会让 Label 变高。** 21.2 只按一行给高度，
>    多出来的行被齐腰切掉 —— 0.6.0 截图里那半行「鬼画符」就是它。
>    凡是可能换行的文本，一律「自己折行（`wrap_text`）+ 高度 = 行数 × 行高」。
> 4. **页脚不要套底色。** 0.6.0 给「诊断 / 联系作者 / 检查更新」加了胶囊底，
>    底部四个灰方块和输入框撞脸，用户原话是「为什么变成了在框里」。

---

## 1. 网格：4px 基线，但 VGap 要减 8

Fusion 的每个 `VGroup` / `HGroup` 自带约 4px spacing；`VGap(n)` 本身又是一个 item，
两侧各叠一次 spacing。**所以两个元素之间的实际距离 = VGap 参数 + 8。**

代码里只允许用下面四档，并且已经折算成 VGap 参数：

| 实际间距 | VGap 参数 | 用途 |
|---|---|---|
| 8 | `VGap(0)` | 标题与其正文 |
| 12 | `VGap(4)` | 步骤标题与其内容 |
| 16 | `VGap(8)` | 细分隔线上下、结果与页脚 |
| 20 | `VGap(12)` | 两个步骤之间 |

不要再出现 `VGap(2)` / `VGap(6)` 这种「看着差不多」的值 —— 0.4.x 的版面就是被
10 / 14 / 16 / 20 混着排，肉眼觉得不齐，量出来确实不齐。

## 2. 字号：只有三档

| 字号 | 字重 | 颜色 | 用途 |
|---|---|---|---|
| 15 | 600 | `#EDEDF0` | 产品名、草稿名 |
| 13 | 600 | `#EDEDF0` / `#9A9AA2` | 步骤名（「读取草稿」） |
| 13 | 400 | `#9A9AA2` / `#EDEDF0` | 正文、说明、输入框、按钮文字 |
| 11 | 400 | `#6C6C74` | 状态字、版本号、页脚按钮 |

0.4.x 是 18 / 15 / 13 / 12 / 11 五档，0.5.0 收到四档（步骤名 12）：1px 的差别
在真机上看不出来，只让整页同时存在三种几乎一样大的字。**层级靠字重和颜色，
不靠 1px 的字号。** 步骤名现在回到 13 + 600。

## 3. 控件：一个尺寸，两种填充

| 项目 | 值 | 说明 |
|---|---|---|
| 高度 | **34** | 行高 18 + 上下 padding 7×2 + 边框 1×2 |
| 宽度 | **120**（按钮） | `min-width` / `max-width` 同时锁死 |
| 圆角 | **8** | 按钮、输入框一致 |
| 边框 | **1px** | 主按钮也画一圈与底色同色的边框 |

- 主按钮 = 实心蓝（`#3B82F6`）+ 白字；次按钮 = 透明底 + `#3A3A40` 描边；
  禁用 = 透明底 + `#2E2E33` 描边 + `#6C6C74` 字。
- **主按钮那圈同色边框不能省**：省掉就是 32 对 34，截图上第一眼就能看出来。
- **主按钮不能加粗**：粗体字面的行高不同，两颗按钮会差 7px，字也看着大一号。
- 宽度必须锁死：文字长短不同（5 字 vs 4 字），靠内容撑会是 118 对 114。
- 高度不设 `MinimumSize`：21.2 不把布局高度分给 Button，定高只会把字切掉。

## 4. 颜色：整屏只有一个实心蓝

| 令牌 | 值 | 用途 |
|---|---|---|
| `C_ACCENT` | `#3B82F6` | 主按钮、「检查更新」、「执行中…」 |
| `C_OK` | `#34C759` | 「就绪」 |
| `C_TEXT` / `C_SUB` / `C_DIM` | `#EDEDF0` / `#9A9AA2` / `#6C6C74` | 三级灰阶 |
| `C_LINE` / `C_LINE_SOFT` | `#2E2E33` / `#26262A` | 强 / 弱分隔线 |
| `C_FIELD` / `C_PILL` | `#26262A` / `#222226` | 输入框底色 / 状态胶囊底色 |

步骤序号的徽标用中性灰（`#303038`），**不用蓝**：主按钮已经是整屏唯一的实心蓝，
再添两个蓝圆点会把视线拉成三处。

## 5. 状态：只有一行字，颜色就是状态

每个步骤标题右侧跟一句 11px 的状态：灰「等待剪映」、绿「就绪」、蓝「执行中…」。

0.5.0 在中间夹过一颗 6px 的点 —— 它左右间距都不是整数倍，排出来像一条跑偏的
项目符号；而状态字本身已经换色，点是重复信息。现在没有点。

状态字紧跟标题（不是右对齐到面板边缘）：贴右会正好落在下一行按钮的正上方，
看起来像压住了按钮，而且离标题 300px，读起来也不像这一步的属性。

## 6. 版面的竖轴

```
产品名 / 副标 · 状态胶囊
────────────────────────      细分隔线（强）
① 读取草稿 就绪
   草稿名（1 行，超长省略）        [送入达芬奇]
   一句现状（固定 2 行 = 34px）
────────────────────────      细分隔线（弱）
② 命名并写回 等待前一步
   [草稿名输入框]                 [写回剪映]
   结果（固定 3 行 = 51px）
                              （弹簧，只吃这一段的余量）
诊断 · 联系作者          v0.6.1 检查更新
                              10px 底部留白
```

- 左列吃满剩余宽度，右列固定 120 —— 两行的按钮左右边缘天然对齐。
- **页脚是裸字，不是按钮也不是胶囊**：左边两项 `C_SUB` 11px，中间一个 `C_DIM`
  的「·」，右边版本号 `C_DIM`、「检查更新」`C_ACCENT`。
  左右 `padding` 归零，页脚两端才和上面的正文对齐在同一条竖轴上。
- **弹簧放在结果行和页脚之间**：面板在达芬奇里可以被拉高，弹簧若在内容中间，
  窗口一高就变成「上半页有字、中间一大块空、底下再冒两行」。现在内容从顶部
  连续排完，多余高度全部落在页脚上方，页脚照旧贴底，像一条状态栏。
- 窗口 460×475（含标题栏），内容约 436，差的那十几像素给弹簧。
  **结果固定 3 行**：写回成功那条要把帧数、分辨率、剪映是否又改过说完，
  两行装不下，第三行会被切 —— 而「不含这些改动」正是最该看见的。

## 7. 怎么验证

1. **改之前先看预览**：`python build/preview_panel.py idle|ready|busy`。
   预览脚本用同一套字号 / 行高 / 间距数字，比例和达芬奇里基本一致。
2. **跑测试**：`tests/test_panel_slim.py` 里有八条硬约束 ——
   两按钮共用一套尺寸令牌（且不含 `font-weight`）、输入框与按钮同高、
   状态字紧贴标题、字号只有三档、窗口尺寸与内容对得上、
   文本高度 = 行数 × 行高、折行不超宽、页脚必须是裸字（不许有底色 / 边框）。
3. **看日志**：面板启动时往 `%LOCALAPPDATA%\ColorPass\panel\colorpass_panel.log`
   写一行 `geometry`：

   ```
   geometry win={...} btnSend={...} ... footer_bottom=397/405 buttons=120x34/120x34 input_vs_button=ok
   ```

   - `footer_bottom` 是**窗口坐标系里的绝对底边**（0.5.0 报的是相对父容器的 y，
     永远等于 22，纯粹骗自己）；一旦超过窗口高度会标 `OVERFLOW`。
   - `buttons=` / `input_vs_button=` 出现 `MISMATCH` 说明 Fusion 没按 QSS 走，
     回来改令牌。
   - `jybInfo=246x34/2L` 是「宽×高/文本行数」：行数 × 17 超过高度会标 `CLIP`，
     说明又出现了「折了行却没给够高度」的裁切。
